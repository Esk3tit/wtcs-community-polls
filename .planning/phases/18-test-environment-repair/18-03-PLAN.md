<objective>
Implement the deferred fault-injection test coverage for the server-side `create-poll` Edge Function, made fail-safe and non-global per REVIEWS HIGH-2 and HIGH-3. Four file changes: (1) extend `e2e/fixtures/seed.sql` with a `test_fault_config` table + BEFORE UPDATE/DELETE triggers on `polls`, harden the `app.e2e_seed_allowed` guard to fail-closed (`ON_ERROR_STOP`), and TRUNCATE stale sentinels on re-seed; (2) serialize the integration runner in `vitest.config.integration.ts`; (3) add `-v ON_ERROR_STOP=1` to both CI fixture-seed `psql` steps; (4) replace the end-of-file deferral comment with two title-scoped, `try/finally`-guarded `it()` test cases.

Purpose: The `create-poll` EF runs entirely server-side, so the only viable interception layer is a real DB-level BEFORE trigger.

REVIEWS HIGH-2 (Codex HIGH + Cursor HIGH, verified): `vitest.config.integration.ts` sets no parallelism control, so Vitest's default file-level parallelism is active. A global wildcard sentinel + a "newest `poll_created`" audit lookup means a concurrently-running sibling integration file can (a) hit the armed trigger and fail spuriously, and (b) steal the newest audit row. Fix BOTH defenses: serialize the suite (`fileParallelism: false`) AND scope the fault row + audit lookup to this test's unique poll title token instead of a global wildcard + "newest" — so the design is correct even if parallelism is re-enabled later.

REVIEWS HIGH-3 (Codex HIGH, verified): the disarm path was not `try/finally` and `afterEach` did not unconditionally clear `test_fault_config`, so a thrown assertion before disarm leaves a fault row armed and poisons the rest of the suite. Separately, the `app.e2e_seed_allowed` guard is a top-of-file `DO $$ ... RAISE EXCEPTION` block, but CI runs `psql -f e2e/fixtures/seed.sql` WITHOUT `-v ON_ERROR_STOP=1` (ci.yml lines 107 & 207) — per PostgreSQL psql semantics, the unguarded run prints the error and then CONTINUES executing the remaining DDL, so the guard does not fail-closed. Appending trigger DDL after the guard amplifies this. Fix: `try/finally` + unconditional `afterEach` cleanup; `\set ON_ERROR_STOP on` in seed.sql (and/or single-transaction wrap) AND `-v ON_ERROR_STOP=1` on both CI psql calls.

Branch (a) verifies UPDATE-fails + DELETE-succeeds = `poll_created` audit row only + poll absent. Branch (b) verifies UPDATE-fails + DELETE-also-fails = `poll_created` + `poll_created_orphaned` rows + poll orphaned.

Output: `create-poll-results-hidden.test.ts` reports `Tests 6 passed (6)` (4 existing + 2 new), no leaked polls, empty `test_fault_config` after the run, the integration runner single-threaded, and the seed guard fail-closed in CI. Full suite exits 0 locally and in CI.
</objective>
