## Scope Note

**This phase has exactly one UI change: UIDN-06.**

UIDN-06 restores semantic `<h2>` headings in `AdminsList` and `CategoriesList` that
were demoted to non-semantic `<div>` CardTitle elements with ARIA overrides
(`role="heading" aria-level={2}`) during Phase 17. The fix is:

1. Add `asChild` polymorphism to `CardTitle` in `src/components/ui/card.tsx` using
   `Slot.Root` from `radix-ui` (identical pattern to `Button` and `Badge`).
2. Replace the ARIA-workaround call sites with `<CardTitle asChild><h2>…</h2></CardTitle>`.
3. Remove the `role="heading" aria-level={2}` props from those two call sites.

**Visual rendering must be identical before and after.** Only the DOM element type and
accessibility semantics change. No new visual design, no layout changes, no new
color/spacing/copywriting requirements.

The DBHY-05 database migration in this phase has no UI surface.

## Component Contract: CardTitle asChild

This is the only structural component change in the phase.

### Before (current — ARIA workaround)

```tsx
<CardTitle role="heading" aria-level={2} className="text-base">
  Admins
</CardTitle>
```

Rendered DOM: `<div data-slot="card-title" role="heading" aria-level="2" class="leading-none font-semibold text-base">Admins</div>`

### After (this phase — semantic heading)

```tsx
<CardTitle asChild className="text-base">
  <h2>Admins</h2>
</CardTitle>
```

Rendered DOM: `<h2 data-slot="card-title" class="leading-none font-semibold text-base">Admins</h2>`

### Visual invariant

The rendered heading must be visually identical before and after. The only observable
changes are:

1. DOM element: `div` → `h2`
2. ARIA role: `role="heading" aria-level="2"` (ARIA override) → native heading semantics
3. `role` and `aria-level` props: removed from call sites

### CardTitle primitive extension

File: `src/components/ui/card.tsx` — `CardTitle` function only.

```typescript
// Add import at top of file:
import { Slot } from "radix-ui"

// Replace CardTitle with:
function CardTitle({
  className,
  asChild = false,
  ...props
}: React.ComponentProps<"div"> & { asChild?: boolean }) {
  const Comp = asChild ? Slot.Root : "div"
  return (
    <Comp
      data-slot="card-title"
      className={cn("leading-none font-semibold", className)}
      {...props}
    />
  )
}
```

Pattern source: identical to `button.tsx` and `badge.tsx` in this codebase — use
`Slot.Root` (not `Slot` directly) because `radix-ui` 1.4.3 exports `Slot` as a namespace
object with `.Root` as the primitive.

### Accessibility assertion

Both component unit tests already contain `getByRole('heading', { level: 2 })`.
After the fix, these assertions pass because the element is a real `<h2>`, not because of
the ARIA override. No new test files needed.

Files to update (remove ARIA workaround comments, no logic changes):
- `src/__tests__/admin/admins-tab.test.tsx`
- `src/__tests__/admin/categories-tab.test.tsx`
