<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → package.json | The lint-staged@17.0.x package is resolved from the npm registry by dependabot's automated bump |
| dependabot branch → main | The PR diff is authored by GitHub's dependabot bot; merge introduces the new lockfile state |
| local pre-commit hook → developer environment | npx lint-staged executes eslint and tsc in the developer's shell; any compromise of lint-staged would run in that context |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering | npm registry / lint-staged@17.0.x package | mitigate | Package is 8+ year old, 3.7M weekly downloads, official maintainer. Dependabot-sourced PRs only — no manual version edits. Registry verified in RESEARCH.md Package Legitimacy Audit. |
| T-21-02 | Tampering | Transitive dependency injection via lockfile | mitigate | The PR diff (package-lock.json) is reviewed by CodeRabbit/gemini/greptile bots before operator approval. CI (lint-and-unit) runs npm ci against the bumped lockfile and executes eslint + tsc + vitest + playwright, acting as a behavioral tripwire for any injected malicious transitive dep. |
| T-21-03 | Tampering | Merging without the bump being dependabot-authored | mitigate | PR #34 author is verified as `app/dependabot` (`gh pr view 34 --json author`). Operator reviews the PR diff before approving. No manual version edits are permitted per D-04. |
| T-21-04 | Elevation of Privilege | lint-staged v17 pre-commit hook executing arbitrary code | accept | lint-staged is a dev-only tool that runs in the developer's environment, not in production. The existing hook commands (eslint, tsc) are project-defined in package.json. No production code path is affected. Risk is limited to developer machine; accepted for a dev-only devDep. |
| T-21-SC | Tampering | npm install introduces compromised package | mitigate | slopcheck already cleared all packages in RESEARCH.md Package Legitimacy Audit. All packages are established project dependencies (not new additions). Operator merge gate is blocking — no auto-merge. |
