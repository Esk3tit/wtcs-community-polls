<objective>
Eliminate the results "flash": a voted poll with `results_hidden=true` briefly leaks real vote counts/percentages (~1-2s) on initial load before the hidden flag resolves and censors them.

Purpose: Authentic, manipulation-resistant results are the core value of the product. A 1-2s leak of counts an admin intentionally hid undermines that guarantee (Tim observed it live).

Output: A surgical fail-closed gating change so "results_hidden unknown" renders as hidden, plus a regression test that pins the first-paint contract. No SSR, no architecture change.
</objective>

<root_cause>
Confirmed during planning by reading the three files:

- `useVoteCounts` (src/hooks/useVoteCounts.ts) returns `resultsHidden: Map<string, boolean>`. It only populates an entry for a poll AFTER the `polls_effective` round-trip resolves (line 103-111). Before that first resolution, the poll has NO entry — a map-miss. A map-miss is therefore the "unknown / not-yet-fetched" state, and it is currently indistinguishable from "fetched, results_hidden=false".
- `SuggestionList.tsx` line 153 passes `resultsHidden={resultsHidden.get(suggestion.id) ?? false}`. The `?? false` is the bug: it collapses the unknown window to "visible". This is **fail-OPEN**.
- `SuggestionCard.tsx` line 144 gates: `userChoiceId && resultsHidden ?` placeholder `: userChoiceId ?` ResultBars (renders counts) `: ChoiceButtons`. With `resultsHidden=false` on first paint, a voted poll falls through to ResultBars and paints counts — the leak — until the next render (~when the 8s-cadence fetch resolves) flips it to `true` and censors it.

Decision point #1 (where the decision is made): `SuggestionCard.tsx:144`, boolean `resultsHidden`. Initial/unknown state today: `false` (visible). Bug = unknown falls through to "show results".

Decision point #2 (hook signal): The hook does NOT need a new signature. Map-miss already uniquely encodes "unknown" because every voted poll id is queried each fetch and gets an entry on success — a persistent miss only exists in the pre-first-resolution window. So the minimal, surgical fix is to flip the CONSUMER default to fail-closed: `?? true`.

Trade-off (recorded per task instruction): A tri-state value (`boolean | 'unknown'`) on the map would make "unknown" explicit in the type. We reject it as heavier for no behavioral gain — the map-miss already IS the unknown signal, and flipping the consumer default is a one-line change with identical fail-closed semantics. We document the contract with a hook comment so the implicit "miss = unknown = hidden" invariant is not lost. The worst case of `?? true` is a brief "Results temporarily hidden by admin" placeholder (or, for a never-voted poll, ChoiceButtons — unaffected, since the placeholder branch also requires `userChoiceId`) until the flag resolves — never leaked counts.

Both views covered: `topics.tsx` (status="active") and `archive.tsx` (status="closed") both render through `SuggestionList` → `SuggestionCard`. Fixing the single `SuggestionList` call site covers both. (Verified: no other component consumes `resultsHidden` for public results rendering — `useVoteSubmit`/admin/form usages are unrelated.)
</root_cause>
